What is MODBUS?

MODBUS is a simple, open industrial communication protocol introduced by Modicon (Schneider Electric) in 1979. It provides a standard way devices (PLCs, sensors, HMIs, SCADA) talk to each other.

Why use MODBUS?

  • Simple, lightweight, widely supported across vendors.
  • Standard data model and function codes — easy integration.
  • Works over serial (RS‑485 / RS‑232) as RTU/ASCII and over Ethernet as TCP.

Master / Slave model

Master (Client) — initiates requests (example: SCADA/HMI).

Slave (Server) — replies to requests (example: sensor, PLC). Slaves never start communication.

Typical ID range: 1–247. Why this range?

MODBUS types (layers)

Common variants:

  • RTU — binary frames over RS‑485/RS‑232 (most common).
  • ASCII — ASCII text frames, slower, easier to debug (rarely used today).
  • TCP — runs over Ethernet (TCP port 502), MBAP header replaces CRC &. device addressing.

4xxxxHolding RegistersRead/WriteAnalog outputs, configuration

Important function codes

Remember these common ones:

  • 01 — Read Coils
  • 02 — Read Discrete Inputs
  • 03 — Read Holding Registers
  • 04 — Read Input Registers
  • 05 — Write Single Coil
  • 06 — Write Single Register
  • 15 (0F) — Write Multiple Coils
  • 16 (10) — Write Multiple Registers

MODBUS RTU frame (byte layout)

Typical RTU frame structure:

// Slave ID | Function | Data | CRC (2 bytes)
01 03 00 10 00 02 C5 CD

// Meaning:
// 01 -> Slave 1
// 03 -> Read holding registers
// 00 10 -> Start address 0x0010
// 00 02 -> Read 2 registers
// C5 CD -> CRC16

MODBUS TCP frame (MBAP + PDU)

TCP removes CRC and adds MBAP header (7 bytes):

00 01 00 00 00 06 01 03 00 10 00 02

// MBAP header: transaction id, protocol id, length, unit id
// PDU: function + data

Quick real-world example

A temperature sensor might expose:

  • 30001 — Temperature (Input Register)
  • 40010 — Calibration value (Holding Register)
  • 00005 — Heater ON/OFF (Coil)

SCADA polls the input register to read temperature periodically.

Implementation notes (embedded / C)

  • Understand UART and RS‑485 transceiver control (DE/RE lines).
  • Implement CRC‑16 (Modbus polynomial), a receive state machine, and timeout handling.
  • Map registers to application variables and implement handler for function codes 03/06/16 etc.

Summary — TL;DR

MODBUS is a simple, reliable industrial protocol used to read/write memory areas (coils/registers) between a master and one or more slaves. RTU (serial) and TCP (Ethernet) are the most common flavors.
