Discrete Inputs in Modbus

A deep dive into how Modbus Discrete Inputs are implemented in firmware, how they relate to hardware signals, and how they differ from coils and registers.

What Is a Discrete Input?

A Discrete Input is a read-only, 1-bit data point that represents the state of a physical digital signal.

Discrete Inputs reflect hardware reality, not software commands.

In Modbus, Discrete Inputs are accessed using Function Code 02 (Read Discrete Inputs).

Why Discrete Inputs Exist Separately

Although Discrete Inputs and Coils are both 1-bit values, they serve fundamentally different roles.

  • Discrete Inputs are controlled by hardware
  • They cannot be written by software
  • They provide feedback and verification
  • They improve safety and fault detection
Separating inputs from outputs prevents software from accidentally or intentionally hiding real-world faults.

Discrete Inputs at the Hardware Level

Discrete Inputs originate from physical electrical signals connected to the device:

  • Push buttons
  • Limit switches
  • Proximity sensors
  • Relay feedback contacts

These signals are wired to digital input pins of a microcontroller or PLC.

How Discrete Inputs Are Implemented in Firmware

Inside firmware, a Discrete Input is implemented as a boolean variable that is updated by reading a GPIO pin. 


// Firmware variables
bool di_start_button;
bool di_limit_switch;
bool di_motor_feedback;

These variables are refreshed periodically in the main loop or an ISR. 


// Read hardware pins
di_start_button   = READ_GPIO(PIN_START_BTN);
di_limit_switch   = READ_GPIO(PIN_LIMIT_SW);
di_motor_feedback = READ_GPIO(PIN_MOTOR_FB);

Mapping Discrete Inputs to Modbus

Modbus does not expose firmware variables directly. Instead, discrete inputs are mapped into a logical Modbus address space. 


// Modbus discrete input map
bool modbus_discrete_inputs[32];

// Mapping
modbus_discrete_inputs[0] = di_start_button;
modbus_discrete_inputs[1] = di_limit_switch;
modbus_discrete_inputs[2] = di_motor_feedback;
Addressing like 10001 is a documentation convention — firmware only uses array indices.

Read Flow (Function Code 02)

  1. Master sends Read Discrete Inputs request (FC02)
  2. Firmware reads GPIO-backed variables
  3. Bits are packed into bytes
  4. Response frame is transmitted
  5. Master decodes individual input states

Firmware Pseudocode


function handle_fc02(start_addr, quantity):
    for i = 0 to quantity-1:
        bit[i] = discrete_inputs[start_addr + i]
    pack_bits_into_bytes(bit[])
    send_response()

Relation to Registers

Discrete Inputs are not registers and are not stored as 16-bit values.

Type Firmware Form Purpose
Discrete Input bool Hardware feedback
Coil bool Software command
Holding Register uint16_t Configuration
Input Register uint16_t Measurement

Why This Design Matters

  • Prevents software from falsifying hardware state
  • Improves diagnostics and safety
  • Matches real electrical wiring
  • Makes SCADA systems reliable
Discrete Inputs tell you what the system is, not what it was told to do.

Real-World Examples

  • Push button pressed or released
  • Limit switch activated
  • Motor contactor feedback
  • Door open / closed indication
  • Emergency stop feedback
