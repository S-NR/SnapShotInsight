What is Broadcast in MODBUS?

Broadcast is a special MODBUS feature where the master sends a message using slave ID 0. Every slave on the network accepts and executes it. No slave sends a response back. This allows one‑to‑many control without flooding the bus.

Why Broadcast Exists

  • To configure many MODBUS devices at once.
  • To trigger synchronized actions (reset, start, stop, sample).
  • To reduce traffic when updating several slaves.
  • To ensure no reply collisions occur on RS‑485.

Important Broadcast Rules

  • Address used must be 0.
  • No slave replies — prevents two devices from sending responses at the same time.
  • Only write type function codes are allowed (05, 06, 0F, 10).
  • Not available in MODBUS TCP — only RTU/ASCII.
  • Master does not wait for confirmation.

How Broadcast Works Internally

Every slave device listens to the bus. When a frame with ID 00 appears:

  • The frame is validated (timings + CRC).
  • If valid, it is executed by all slaves.
  • No device sends back a reply frame.

This prevents response collisions on RS‑485 lines.

Broadcast Frame Example

// Write Single Register (Function 06)
00 06 00 10 00 64 88 32

00 → Broadcast (all slaves)
06 → Write Single Register
0010 → Register Address
0064 → Value (100)
8832 → CRC16

Common Use Cases

  • Resetting all connected devices.
  • Starting measurement on all sensors simultaneously.
  • Setting default configuration on power‑up.
  • Writing calibration data to many units at once.
