CRC – Ground Level Explanation (Modbus RTU)

1. Why CRC Exists

In real communication systems (like Modbus RTU), data travels through noisy environments:

  • Electrical interference
  • Long cables
  • Loose connections
  • Timing distortions

Because of this, bits can flip: 

Sent : 0100 0011
Received : 0100 1011   ← error

CRC (Cyclic Redundancy Check) allows the receiver to:

  • Detect corrupted data
  • Reject invalid frames
  • Request retransmission

CRC does not fix errors — it detects them reliably.

2. What CRC Really Is (Intuition)

CRC is best understood as:

A mathematical fingerprint of the data

Before transmission:

  • Sender calculates CRC from the data
  • Appends CRC to the message

After reception:

  • Receiver recalculates CRC
  • Compares with received CRC

If they differ → data is invalid.

3. Why CRC Uses Binary & Polynomials

Digital systems operate in binary (0 and 1). CRC uses:

  • XOR instead of addition
  • Bit shifting instead of multiplication

CRC math is based on polynomial division, but implemented using:

  • Shift registers
  • XOR gates

This makes CRC:

  • Fast
  • Hardware-friendly
  • Very reliable

4. CRC Parameters Used by Modbus RTU

CRC Width      : 16 bits
Initial Value  : 0xFFFF
Polynomial     : 0xA001
Bit Order      : LSB first
Shift Direction: Right
Final XOR      : None

Important: 0xA001 is the reflected form of polynomial 0x8005.

5. How CRC is Calculated (Step-by-Step)

Example Modbus Frame (without CRC)

01 03 00 10 00 02

Step 1: Initialize CRC

CRC = 0xFFFF

Step 2: Process Each Byte

For each byte:

  • XOR byte with low byte of CRC
  • Process 8 bits
Repeat 8 times:
    If (CRC LSB == 1)
        CRC = (CRC >> 1) XOR 0xA001
    Else
        CRC = CRC >> 1

This mimics a hardware shift register.

6. Why Modbus Uses LSB First

Modbus RTU was designed for:

  • Simple UARTs
  • Low-end microcontrollers
  • Shift-register based hardware

Processing LSB first:

  • Simplifies hardware
  • Matches UART bit order
  • Reduces logic gates

7. CRC Transmission Order

After calculation: 

CRC = 0xCEC5

Modbus sends: 

CRC Low Byte  → C5
CRC High Byte → CE

Low byte is always transmitted first.

8. Common CRC Mistakes

  • Using left shift instead of right
  • Using polynomial 0x8005 directly
  • Processing MSB first
  • Swapping CRC bytes
  • XOR with high byte instead of low byte

9. Final Takeaway

CRC in Modbus RTU is:

  • Simple in logic
  • Powerful in error detection
  • Designed for hardware efficiency

Once you understand the bit shifts and XOR, CRC stops being magic and becomes predictable.
