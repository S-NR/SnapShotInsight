Function Code 02 — Read Discrete Inputs

A detailed explanation of how Modbus Function Code 02 works, why it exists, and how it is used in real industrial systems.

← Back

Overview

Function Code 02 (0x02) is used by a Modbus Master (Client) to read the state of Discrete Inputs from a Modbus Slave (Server).

Discrete Inputs represent read-only digital signals coming from the physical world.

Purpose

The purpose of Function Code 02 is to monitor external digital input signals without allowing them to be modified by software.

  • Inputs are controlled by hardware, not software
  • Only reading is allowed
  • Improves safety and system reliability

What It Does

When a master sends a request using Function Code 02, the slave responds with the current state of one or more discrete inputs.

Each input is returned as a single bit:

  • 0 → Input OFF / Inactive
  • 1 → Input ON / Active
Multiple discrete inputs are packed into bytes to reduce communication bandwidth.

Discrete Inputs in the Modbus Data Model

Property Description
Data Type 1 bit per input
Access Read-only
Typical Address Range 1xxxx (logical reference)
Controlled By Physical hardware signals

Modbus RTU Request Frame

A typical request to read discrete inputs looks like this: 


| Slave ID | Function | Start Address | Quantity | CRC |
|  0x01    |  0x02    |    0x0000     |  0x0008  | CRC |
  • Start Address → First discrete input to read
  • Quantity → Number of inputs to read

Modbus RTU Response Frame


| Slave ID | Function | Byte Count | Input Status | CRC |
|  0x01    |  0x02    |   0x01     |   0b01011001 | CRC |

Each bit in the response represents one discrete input. The least significant bit (LSB) corresponds to the lowest input address.

Operational Workflow

  1. Master sends a Read Discrete Inputs request
  2. Slave reads physical input hardware
  3. Slave packs input states into bytes
  4. Slave sends the response frame
  5. Master decodes individual input bits

Pseudocode Example


send_request(slave_id, function_code=0x02, start_addr, quantity)

response = receive_response()

for i from 0 to quantity-1:
    input_state[i] = (response.data >> i) & 0x01

Why It Is Used

  • Protects input signals from software modification
  • Clearly separates inputs from outputs
  • Improves fault detection and diagnostics
  • Matches real-world electrical behavior
If software could write to inputs, it could hide real faults. Read-only access prevents this.

Real-World Examples

  • Push button pressed or released
  • Limit switch reached
  • Proximity sensor detection
  • Door open / closed indication
  • Emergency stop feedback
