Coils vs Discrete Inputs

Clarifying Modbus addressing, data types, and firmware responsibilities — what you can choose freely, and what you must not.

The Core Truth

You can choose any address number.
You cannot freely choose the data type.

In Modbus, the address is just an index. The meaning of the data comes from how it is mapped in firmware.

Are Addresses Your Choice?

Yes. Address numbers in Modbus are simply offsets. Modbus does not enforce meaning based on address values. 


// All of these are valid
coils[0]  = motor_start;
coils[15] = valve_open;

discrete_inputs[0]  = limit_switch;
discrete_inputs[27] = door_sensor;
Logical addresses like 00001 or 10001 exist only in documentation — not in Modbus frames.

What You Cannot Choose Freely

While addresses are flexible, the type of data (coil vs discrete input) is determined by signal origin.

Signal Origin Correct Modbus Type
Software-controlled output Coil
Hardware-driven input Discrete Input

Wrong Design: Hardware Input as a Coil

Mapping a physical input as a coil allows software to overwrite real-world state. 


// ❌ Wrong
coils[0] = READ_GPIO(LIMIT_SWITCH_PIN);

This allows a Modbus master to write to the input: 


// SCADA can now do this (dangerous)
FC05 → Write Coil 0 = ON
This design hides faults and breaks safety guarantees.

Wrong Design: Hardware Output as a Discrete Input

Mapping a controllable output as a discrete input removes software control. 


// ❌ Wrong
discrete_inputs[0] = motor_start_command;

Result:

  • SCADA cannot control the output
  • Only reads are possible
  • The system becomes unusable remotely

Correct Design Pattern

Commands and feedback must be separated. 


// Command (software → hardware)
coils[0] = motor_start_command;

// Feedback (hardware → software)
discrete_inputs[0] = READ_GPIO(MOTOR_FEEDBACK_PIN);
Aspect Result
Control Yes
Feedback Yes
Fault detection Reliable
Safety Preserved

Why Modbus Allows Incorrect Mapping

Modbus is a transport protocol. It does not understand hardware semantics or safety requirements.

  • No data-type enforcement
  • No hardware awareness
  • Responsibility lies with firmware design
Modbus assumes the firmware engineer understands the system.

The Rule to Remember


Address numbers are free.
Meanings are not.

Choose addresses based on organization. Choose data types based on physical reality.
