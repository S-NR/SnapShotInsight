Function Code 03 — Read Holding Registers

← Back

Purpose

Function Code 03 is used to read values from holding registers, which are read/write registers intended for configuration parameters, setpoints, and internally calculated values.

What is a Holding Register?

A holding register is a 16-bit memory location inside a MODBUS slave device. Unlike inputs, holding registers can be both read and written by a MODBUS master.

  • Size: 16-bit (2 bytes)
  • Access: Read / Write
  • MODBUS range: 40001 – 49999 (logical)
  • Used for: Parameters, setpoints, totals

What Function Code 03 Does

FC03 allows the MODBUS master to request one or more consecutive holding registers from a slave device.

The slave responds by returning the values stored in those registers without modifying them.

FC03 Request and Response Frame Format

Request Frame (Master → Slave)


    | Slave ID | Function | Start Addr Hi | Start Addr Lo | Qty Hi | Qty Lo | CRC Lo | CRC Hi |
    |   1 B    |   1 B    |      1 B      |      1 B      |  1 B   |  1 B   |  1 B   |  1 B   |

Response Frame (Slave → Master)


    | Slave ID | Function | Byte Count | Data Hi | Data Lo | ... | CRC Lo | CRC Hi |
    |   1 B    |   1 B    |    1 B     |  1 B    |  1 B    |     |  1 B   |  1 B   |

The Byte Count field equals Quantity × 2, since each holding register is 16 bits (2 bytes).

Why Function Code 03 Is Used

  • To read configuration parameters
  • To verify setpoints written earlier
  • To monitor calculated internal values
  • To fetch totals, counters, and limits

Any value that can be written using FC06 or FC16 should be read back using FC03.

Real-World Examples

  • Flow totalizer values (often 32-bit or 64-bit)
  • Speed or pressure setpoints
  • Alarm thresholds
  • Calibration constants

Addressing of Holding Registers

Holding registers are commonly documented using the 40001-based notation. 


Register 40001 → Address 0x0000
Register 40010 → Address 0x0009

Holding Register Memory View

40001 Speed Setpoint
40002 Pressure Limit
40003 Flow Total (High)
40004 Flow Total (Low)

FC03 reads one or more of these registers sequentially, starting from a given address.

Note: The MODBUS protocol itself uses zero-based addressing. The 4xxxx format is only for documentation clarity.

Protocol Limits and Rules

  • Maximum registers per FC03 request: 125
  • Maximum response data bytes: 250
  • Quantity must be greater than zero
  • Requested address range must exist in the slave

Requests violating these limits result in an Illegal Data Address or Illegal Data Value exception.

Firmware Implementation

Internally, holding registers are typically implemented as an array of 16-bit variables mapped to firmware data. 


uint16_t holding_registers[HOLDING_REG_COUNT];

Each register index corresponds to a specific variable.

FC03 Exception Handling

If the slave cannot process the request, it returns an exception response instead of normal register data.

Exception Response Format


| Slave ID | Function (0x83) | Exception Code | CRC Lo | CRC Hi |

Common Exception Codes

  • 0x01 — Illegal Function
  • 0x02 — Illegal Data Address
  • 0x03 — Illegal Data Value

The function code in an exception response is the original function code with its MSB set (0x03 → 0x83).

Pseudocode Example


void handle_fc03(uint16_t start, uint16_t quantity)
{
    if(start + quantity > HOLDING_REG_COUNT)
    {
        send_exception(ILLEGAL_ADDRESS);
        return;
    }

    send_byte(SLAVE_ID);
    send_byte(0x03);
    send_byte(quantity * 2);

    for(int i = 0; i < quantity; i++)
    {
        uint16_t value = holding_registers[start + i];
        send_byte(value >> 8);   // High byte
        send_byte(value & 0xFF); // Low byte
    }

    append_crc();
}

Multi-Register Values

Since holding registers are only 16-bit wide, larger values use multiple registers. 


40003 → High word
40004 → Low word

Firmware must clearly define word order and endianness.

Word Order and Endianness

MODBUS defines register order but does not strictly define multi-register word order. Firmware must clearly document this. 


32-bit Value Example:

Register 40003 → High Word
Register 40004 → Low Word

Value = (40003 << 16) | 40004

Always confirm word order when reading multi-register values such as totals or floating-point numbers.

RTU Timing Considerations

  • Minimum 3.5 character silent interval before each frame
  • Slave response timeout must be handled by the master
  • Only one master may transmit at a time

These timing rules ensure reliable frame detection in MODBUS RTU networks.

Key Design Rule

If a value can be written by a MODBUS master, it must be implemented as a holding register.

Holding registers represent the internal state and configuration of a MODBUS device.

Common Implementation Mistakes

  • Using FC03 to read input registers (should use FC04)
  • Incorrect register offset (40001 vs 0)
  • Wrong word order for 32-bit values
  • Ignoring maximum register limits
