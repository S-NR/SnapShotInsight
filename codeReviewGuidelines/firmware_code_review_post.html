Firmware Code Review Guidelines

A structured checklist for reviewing embedded firmware source code. These rules help detect bugs, unsafe memory usage, race conditions, and hardware misuse.

Copilot Review Memory Safety ISR Safety Concurrency Registers DMA Real-Time Watchdog Peripherals State Machine Error Handling

Copilot Review Instructions

  • Scan the entire file or module first
  • Identify issues using the checklist sections
  • Prioritize issues by severity
  • Provide recommended fixes

When reporting issues include:

  • File name
  • Function name
  • Problematic code snippet
  • Risk explanation
  • Recommended fix

Memory Safety

  • Buffer overflow risks
  • Array index out-of-bounds
  • NULL pointer dereference
  • Uninitialized pointers
  • Integer overflow
  • Stack overflow risks

Example Risk

char buf[8];
strcpy(buf, input);

Safer Implementation

char buf[8];
strncpy(buf, input, sizeof(buf)-1);
buf[sizeof(buf)-1] = '\0';

Interrupt Handling (ISR)

  • Long execution time inside ISR
  • Blocking functions inside ISR
  • Shared variables without volatile
  • Race conditions with main loop

Incorrect ISR

void UART_ISR()
{
    printf("RX");
}

ISR should capture the event quickly and exit.

Concurrency and Race Conditions

  • Shared variables between ISR and main protected
  • Atomic access for shared data
  • Critical sections implemented
__disable_irq();
sharedValue++;
__enable_irq();

Hardware Register Access

  • Registers accessed using bit masks
  • No direct overwrite of configuration registers
  • Reserved bits preserved

Bad Example

REG = 0x01;

Better

REG |= (1U << 0);

DMA Safety

  • DMA buffers not modified during transfer
  • Transfer completion checked
  • Buffer alignment correct
  • Cache coherence handled

Real-Time Behavior

  • No blocking delays in critical paths
  • Watchdog serviced in long loops
  • No heavy computation in ISR

Watchdog Handling

  • Watchdog enabled when required
  • Watchdog periodically refreshed
  • No infinite loops without watchdog reset
  • System recovery strategy implemented

Peripheral Usage

  • UART buffers validated
  • SPI transfers protected
  • I2C error conditions handled
  • Timeout mechanisms implemented

State Machine Logic

  • All states handled in switch statements
  • Default case implemented
  • No illegal state transitions
  • Timeout recovery implemented

Error Handling

  • Return values always checked
  • Timeout handling implemented
  • Retry mechanisms defined
  • Error states logged
if(UART_Send(data) != UART_OK)
{
    handleError();
}

Review Severity Levels

  • Critical – crash risk, memory corruption
  • High – functional failures
  • Medium – reliability issues
  • Low – style or maintainability improvements
