1) Connection Overview

MOSI/MISO directions are opposite. SCLK & CS are driven by the master.

2) Timing — Mode 0 (CPOL=0, CPHA=0)

Data is sampled on rising edges in Mode 0. Both MOSI & MISO shift simultaneously (full‑duplex).

3) Topologies — Normal SPI vs Daisy‑Chain

Normal SPI (Star)

Shared MOSI/MISO/SCLK; one CS per slave. Only one slave is active at a time.

Daisy‑Chain SPI

All devices share SCLK & CS. Data shifts through each device like one long shift register; update many nodes with a single frame.

4) Frame Flow — One Transaction

  1. Master pulls CS=0.
  2. Master clocks out bits on MOSI; slave simultaneously drives MISO.
  3. On each valid edge (per CPHA), both sides sample input and shift next output bit.
  4. After N bits (8/16/24/32…), master releases CS=1 to end the frame.
  5. Optional: repeat frames for multi‑byte commands, addresses, and data.

Pros

  • Simple, fast (tens of MHz)
  • Full‑duplex
  • Flexible word size

Cons

  • More pins (CS per slave in normal topology)
  • No built‑in addressing or ACK/NACK
  • Board‑level distances (signal integrity)

5) Practice & Lab Tips

  • Start with Mode 0 @ 1 MHz, 8‑bit frames; send 0xAA, read back a byte.
  • Verify on logic analyzer: label MOSI/MISO/SCLK/CS, confirm sample edges.
  • For daisy‑chain parts, read the device’s bit length per node and clock a full chain length per update.
  • Mind max SCLK per device, setup/hold times, and CPOL/CPHA matching.

Tip: If bytes look bit‑shifted, your CPHA is likely wrong; if inverted‑idle clock, check CPOL.
