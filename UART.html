UART: From Hardware Basics to Embedded-C Integration

A practical, step-by-step guide — hardware, wiring, timing, MCU internals, firmware patterns, and ready-to-use C snippets.

1) Quick overview (what UART is)

UART = Universal Asynchronous Receiver/Transmitter. Asynchronous serial: data is sent bit-by-bit with a shared baud (bit rate) but no separate clock line.

Typical UART frame: start bit (0) + N data bits (LSB first) + optional parity + stop bit(s) (1 or 2). Idle line state is logic 1 (high). Start bit is low.

2) Physical layer & voltage levels

  • TTL/CMOS UART: 0V = LOW, VCC (3.3V or 5V) = HIGH. Used inside MCU and with USB–TTL adapters (FTDI, CP2102).
  • RS-232: ± voltage and inverted logic → needs level-shifter (MAX232).
  • RS-485: differential, multi-drop bus → transceiver chip required.
  • Wiring: TX(A) → RX(B), RX(A) ← TX(B). Always share GND.
  • Cable lengths: TTL — short (few meters at low baud); RS-485 — much longer.

3) Frame timing and baud

Bit time = 1 / baud. Example at 115200 baud → bit time ≈ 8.680556 μs.

UART sampling and baud generator

MCUs commonly oversample (×16 or ×8). Baud divisor formula (×16):

USARTDIV = PCLK / (16 × baud)

Worked example (digit-by-digit rounding):

ParameterValue (example)
PCLK16,000,000 Hz
baud115,200
oversampling16

In the example above the final BRR value used by many HAL implementations is 139 for PCLK=16MHz, baud=115200, oversampling ×16.

🔹 Configuration Settings: Cause & Effect

Configuration Options Effect if Changed
Baud Rate 9600, 115200, etc. Higher baud = faster but error-prone; lower baud = slower but reliable. Must match on both ends.
Word Length 7, 8, 9 bits Defines data bits per frame. If mismatch → data corruption.
Parity None, Even, Odd Error detection. Reduces payload if enabled. Mismatch → parity errors.
Stop Bits 1, 1.5, 2 Frame alignment. More stop bits = tolerant to mismatch but slower. Wrong setting → framing errors.
Oversampling 8x, 16x 16x = more robust, but limits max baud. 8x = allows higher baud, less robust.
Flow Control None, RTS, CTS, RTS/CTS Prevents buffer overflow in high-speed comms. Ignoring can cause data loss.
Mode Async, Sync, Single-wire, LIN, etc. Defines protocol behavior. Async = normal UART; others for special use cases.

Synchronous UART (USART) — Practical Notes

Short summary: Synchronous UART (commonly available as the MCU's USART synchronous mode) uses a separate clock line in addition to TX and RX. The clock is used to sample data bits so start/stop bits are not required and data alignment is driven by the clock.

Key differences (at-a-glance)

FeatureAsynchronous UARTSynchronous UART
Clock lineNoneRequired (CK pin)
Start/Stop bitsUsedNot required (clocked data)
Voltage levelsTTL / RS-232 (hardware dependent)TTL (typically MCU I/O levels)
Typical usePC serial, debug, sensorsMCU↔MCU high-reliability links, some legacy protocols

Recommended hardware to experiment with synchronous UART

  • MCUs with USART (sync mode): STM32 family (USART peripheral), PIC USART, many Atmel/AVR (USART), TI MSP430 — configure in synchronous mode.
  • FPGAs / CPLDs: you can implement custom synchronous serial interfaces and provide/consume clock lines.
  • Multi-protocol bridge chips (advanced): FT2232H / FT4232H or programmable USB controllers (Cypress FX series) can be programmed to emulate sync protocols, but are more complex.
  • Avoid USB→TTL adapters like FT232RL/CP2102/CH340 for sync UART: those provide async TX/RX only and do NOT forward a CK pin to the PC virtual COM port.

Voltage levels & TTL

TTL describes voltage levels (logic_LOW ≈ 0 V, logic_HIGH ≈ MCU VCC e.g. 3.3 V). Synchronous UART simply adds a TTL clock line — the clock is another TTL-level signal and you wire it directly between devices (MCU to MCU) if both use the same voltage domain.

How to wire synchronous UART (MCU ↔ MCU)

Practical tips

  • Master vs Slave: The master generates the CK; the slave samples data on the clock edges. Choose who drives CK and match settings on both devices (clock polarity/phase if configurable).
  • Voltage matching: Ensure both devices use the same IO voltage (e.g., both 3.3 V). Use level shifters if mixing 5 V and 3.3 V devices.
  • PC connectivity: Standard USB↔TTL adapters (FT232RL, CP2102, CH340) do NOT support CK. To log/monitor synchronous traffic on a PC you’ll need a logic analyzer or custom bridge (FT2232H or programmable USB controller).
  • Use existing MCU peripherals: Easiest way to try sync UART is to use two dev boards (e.g., two STM32 Nucleo/Discovery boards) and set one USART to synchronous master and the other to synchronous slave.

When to prefer synchronous UART

  • High-reliability links where clock alignment makes data sampling robust.
  • When you want slightly better efficiency because start/stop bits are not required.
  • When both endpoints are dedicated digital devices (MCUs, FPGAs), not PCs.

Example (STM32)

In CubeMX select the USART peripheral and set Mode → Synchronous (you'll see a CK pin allocated). Configure the CK master/slave role and clock polarity/phase if exposed. Connect CK to peer CK, and TX/RX cross-connected as usual. Test with a simple loopback or echo program between the two MCUs.

Quick checklist to test sync UART:
  1. Both devices use same IO voltage (3.3 V recommended).
  2. One device configured as clock master; the other as slave.
  3. TX ↔ RX, RX ↔ TX, CK ↔ CK connections made.
  4. Observe clock and data with logic analyzer or scope; verify data is sampled on expected edges.

4) What’s inside a typical MCU UART block

  • TX / RX shift registers — shift bits out/in.
  • Baud generator — produces bit clock from PCLK.
  • FIFO — small TX/RX FIFOs (1..32 bytes) buffer bursts.
  • Control registers — word length, parity, stop bits, flow control.
  • Status registers — TXE (transmit empty), TC (transmit complete), RXNE (rx not empty), error flags.
  • Interrupts & DMA — RXNE, TXE, TC, errors; DMA handshake support for high throughput.

5) Flow control options

  • None — simplest.
  • Hardware: RTS / CTS lines.
  • Software: XON/XOFF (in-band ASCII).

6) How to wire & initial tests

  • Loopback: short TX → RX on same UART and send bytes; they should echo back.
  • Connect MCU TX/RX to a USB–TTL adapter (match voltage) and open terminal (PuTTY / Tera Term / minicom) with matching settings.
  • Use logic analyzer / oscilloscope to check idle high, start bit low, bit timing and stop width.

7) Firmware integration steps (high level checklist)

  1. Decide baud, parity, data bits, stop bits, flow control.
  2. Enable peripheral clock (APB / AHB).
  3. Configure pins (GPIO alternate function, speed, pull-ups if needed).
  4. Program baud generator (BRR) using PCLK and oversampling formula.
  5. Configure frame format (8N1 etc.).
  6. Enable receiver and transmitter.
  7. Choose transfer method: polling / interrupt / DMA.
  8. If using interrupts, enable NVIC and implement ISR.
  9. Test with loopback and external terminal.

8) Driver patterns & C code examples

8.1 Portable ring-buffer + IRQ driven approach (platform-agnostic)

Keep low-level hooks separate from portable code. ISR just enqueues bytes; application dequeues.


/* uart_ring.h (portable) */
#include <stdint.h>
#include <stdbool.h>

#define UART_RX_BUF_SIZE 256
typedef struct {
    volatile uint16_t head;
    volatile uint16_t tail;
    uint8_t buf[UART_RX_BUF_SIZE];
} ringbuf_t;

static ringbuf_t rxbuf = {0};

static inline uint16_t next_index(uint16_t i){ return (i + 1) & (UART_RX_BUF_SIZE - 1); }

void uart_isr_on_rx(uint8_t byte) {
    uint16_t n = next_index(rxbuf.head);
    if (n == rxbuf.tail) {
        // overflow: drop or set flag
    } else {
        rxbuf.buf[rxbuf.head] = byte;
        rxbuf.head = n;
    }
}

int uart_read_nonblocking(uint8_t *out) {
    if (rxbuf.head == rxbuf.tail) return 0; // empty
    *out = rxbuf.buf[rxbuf.tail];
    rxbuf.tail = next_index(rxbuf.tail);
    return 1;
}

void uart_tx_blocking(const uint8_t *data, unsigned len) {
    for (unsigned i=0; i<len; ++i) {
        while (!uart_hw_tx_ready()) { /* wait */ }
        uart_hw_writebyte(data[i]);
    }
}

/* Low-level platform hooks to implement:
   bool uart_hw_tx_ready(void);
   void uart_hw_writebyte(uint8_t b);
   void uart_hw_enable_rx_interrupt(void);
   void uart_hw_disable_rx_interrupt(void);
   uint8_t uart_hw_readbyte(void);
*/

Make UART_RX_BUF_SIZE a power-of-two for the mask trick used above; keep ISR short.

8.2 STM32Cube HAL example (common case)


/* Common HAL pattern: receive 1 byte in interrupt and re-arm. */
UART_HandleTypeDef huart2;
uint8_t rx_byte;

void uart_init(void) {
    huart2.Instance = USART2;
    huart2.Init.BaudRate = 115200;
    huart2.Init.WordLength = UART_WORDLENGTH_8B;
    huart2.Init.StopBits = UART_STOPBITS_1;
    huart2.Init.Parity = UART_PARITY_NONE;
    huart2.Init.Mode = UART_MODE_TX_RX;
    huart2.Init.HwFlowCtl = UART_HWCONTROL_NONE;
    huart2.Init.OverSampling = UART_OVERSAMPLING_16;
    HAL_UART_Init(&huart2);

    HAL_UART_Receive_IT(&huart2, &rx_byte, 1);
}

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart) {
    if (huart == &huart2) {
        uart_isr_on_rx(rx_byte);
        HAL_UART_Receive_IT(&huart2, &rx_byte, 1);
    }
}

void uart_send(const uint8_t *buf, size_t len) {
    HAL_UART_Transmit(&huart2, (uint8_t*)buf, len, HAL_MAX_DELAY);
}

8.3 DMA circular RX (high throughput)

Configure UART RX with DMA in circular mode into a large buffer. Periodically compute head = buffer_size - DMA->NDTR (or use the peripheral-specific pointer) and process bytes between tail and head. This avoids per-byte IRQ overhead.

9) FreeRTOS integration ideas

  • ISR pushes bytes into an RTOS queue using xQueueSendFromISR() — consumer task blocks on xQueueReceive().
  • Or ISR signals a task using vTaskNotifyGiveFromISR(), and the task reads a shared ring buffer.
  • Important: UART ISR priority must be at or below configMAX_SYSCALL_INTERRUPT_PRIORITY if using FreeRTOS ISR APIs.

10) Debug checklist — common mistakes & fixes

  • No RX/TX: Did you enable the peripheral clock? Did you set GPIO to alternate function?
  • Wrong baud: Check the PCLK used and recompute BRR; verify oversampling setting.
  • Inverted bits / garbage: Are you accidentally connected to RS-232 without a level shifter?
  • Parity/stop mismatch: Terminal settings must match MCU settings (baud/parity/data/stop).
  • NVIC not enabled or priority wrong → interrupts not firing.
  • Buffer overflow: implement flow control or increase buffer size.
  • DMA not started or wrong direction: double-check DMA stream/channel & direction settings.

11) How I’d proceed on a real board (recommended sequence)

  1. Read your MCU datasheet's UART/USART section (registers & features).
  2. Hook up a USB–TTL adapter to your TX/RX + GND.
  3. Do a loopback test (TX→RX) to validate code path.
  4. Implement IRQ-driven ring buffer first (simple & reliable).
  5. Switch to DMA circular RX for higher throughput if needed.
  6. Add RTS/CTS for hardware flow-control if you see backpressure/overflow.
