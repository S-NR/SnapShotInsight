Doxygen — Complete Guide From Scratch

Understand what Doxygen is, why to use it, how it works, and how to produce HTML and PDF docs with practical examples.

1) What is Doxygen?

Doxygen is a documentation generator that reads your source code, extracts specially formatted comments (doxygen comments), and produces documentation in multiple formats such as HTML (web) and PDF (printable manual via LaTeX).

Key Benefits

  • Keeps docs in sync with code.
  • Automatic cross-references (functions ↔ files ↔ classes).
  • Optional graphs (call/class/dependency) via Graphviz.
  • Supports many languages: C/C++, C#, Java, Python, IDL, etc.

Typical Outputs

  • HTML site with search
  • LaTeX → PDF manual
  • RTF, man pages, XML

2) How Doxygen Works (Conceptual)

  1. You add structured comments near code elements (files, functions, structs, classes).
  2. Doxygen scans your source tree using a configuration file (Doxyfile).
  3. It generates HTML and/or LaTeX. LaTeX can then be compiled to PDF.
// Example (C)
/**
 * @brief Adds two numbers
 * @param a First integer
 * @param b Second integer
 * @return Sum of a and b
 */
int add(int a, int b);

3) Installation (Windows)

Doxygen

  1. Download and install from the official site.
  2. Optional: add doxygen.exe to your PATH.

LaTeX (for PDF)

  1. Install MiKTeX (lighter) or TeX Live.
  2. Enable Install missing packages on the fly and ensure binaries are in PATH.
  3. Verify with: pdflatex --version
For diagrams, install Graphviz and enable DOT support in Doxyfile (see below).

4) Minimal Workflow

  1. Create a config file in your project root: doxygen -g Doxyfile
  2. Edit the key settings (see sample below).
  3. Run Doxygen: doxygen Doxyfile
  4. Open docs/html/index.html for web docs.
  5. Build PDF: go to docs/latex and run make.bat or pdflatex refman.tex (twice).

5) Sample Doxyfile (Good Defaults)

# --- Project ---
PROJECT_NAME           = "MyProject"
PROJECT_BRIEF          = "Firmware and API Documentation"
OUTPUT_DIRECTORY       = docs
OPTIMIZE_OUTPUT_FOR_C  = YES
JAVADOC_AUTOBRIEF      = YES
WARN_IF_UNDOCUMENTED   = YES
WARN_AS_ERROR          = NO

# --- Inputs ---
INPUT                  = ./Sources ./Include
FILE_PATTERNS          = *.h *.c *.hpp *.cpp
RECURSIVE              = YES
EXTRACT_ALL            = YES
EXTRACT_PRIVATE        = NO
EXTRACT_STATIC         = YES

# --- HTML ---
GENERATE_HTML          = YES
SEARCHENGINE           = YES
GENERATE_TREEVIEW      = YES

# --- LaTeX/PDF ---
GENERATE_LATEX         = YES
LATEX_BATCHMODE        = YES
PDF_HYPERLINKS         = YES
USE_PDFLATEX           = YES

# --- Graphs (needs Graphviz) ---
HAVE_DOT               = YES
DOT_IMAGE_FORMAT       = svg
CALL_GRAPH             = YES
CALLER_GRAPH           = YES
CLASS_GRAPH            = YES
COLLABORATION_GRAPH    = YES

# --- Misc ---
QUIET                  = NO

6) Comment Styles & Common Tags

Block & Line Comments

/** Brief description */
void foo(void);

/// Brief description (C++ style)
void bar();

Popular Tags

  • @brief One-liner summary
  • @param Document parameters
  • @return Return value
  • @note, @warning, @todo
  • @file File-level docs
  • @defgroup, @ingroup Grouping APIs

Function Example

/**
 * @brief Initialize UART at a given baud rate.
 * @param baud Desired baud rate (e.g., 115200)
 * @return 0 on success, negative on error
 */
int uart_init(uint32_t baud);

File Example

/**
 * @file drivers/uart.c
 * @brief UART driver implementation for HS25 platform.
 * @author Team
 */

8) Advanced Features

  • Custom Pages: Add Markdown/HTML content via .dox or .md files and list them in INPUT.
  • Diagrams: Enable DOT (Graphviz) to render call graphs and class diagrams.
  • Groups/Modules: Use @defgroup and @ingroup to organize APIs.
  • Private APIs: Toggle visibility with EXTRACT_PRIVATE.

9) Best Practices

  • Keep brief lines short; add details in the body.
  • Document behavior, constraints, error codes, and units.
  • Use consistent tense and style; avoid duplicating code in comments.
  • Run Doxygen in CI to keep docs updated; fail on undocumented if needed.

10) Troubleshooting

  • 'pdflatex' is not recognized → Install MiKTeX/TeX Live and add to PATH, reopen terminal.
  • Graphs not showing → Install Graphviz, set HAVE_DOT=YES, and ensure dot is in PATH.
  • Empty docs → Check INPUT, FILE_PATTERNS, and RECURSIVE settings.
  • Functions missing → Ensure comments are in a recognized style and EXTRACT_ALL=YES (if needed).
  • Broken links/TOC → Run pdflatex multiple times or just use make.bat.

12) Quick Start Commands

# In project root
> doxygen -g Doxyfile
# edit Doxyfile (see sample above)
> doxygen Doxyfile
# HTML: open docs/html/index.html
# PDF:
> cd docs/latex
> make.bat   # or: pdflatex refman.tex (run twice)

13) Optional: No-LaTeX PDF (RTF route)

Set GENERATE_RTF = YES, run Doxygen, open the .rtf in Word, then export as PDF.

That’s it — you now have the concepts, configuration, and commands to produce both HTML and PDF docs from your code comments.
