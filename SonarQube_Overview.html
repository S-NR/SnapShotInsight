What is SonarQube?

SonarQube is a static code analysis tool used to continuously inspect and improve code quality. It detects issues in source code without executing the program.

It helps teams identify problems related to reliability, security, maintainability, duplication, and test coverage early in the development cycle.

Why use SonarQube?

  • Find bugs before code reaches production
  • Improve readability and maintainability
  • Reduce technical debt
  • Improve security awareness
  • Enforce common coding standards across teams

Static Code Analysis

Static code analysis checks the source code without running it. SonarQube scans the code and compares it against predefined rules.

  • Detects logical errors
  • Detects security weaknesses
  • Detects poor coding practices

SonarScanner

SonarScanner is the tool responsible for scanning the source code and sending analysis results to the SonarQube Server.

SonarQube itself does not scan the code. The scanner performs the analysis based on the project type and build system.

Choosing the Right SonarScanner

The scanner depends on how your project is built:

  • Gradle – SonarScanner for Gradle
  • Maven – SonarScanner for Maven
  • MSBuild – SonarScanner for MSBuild (.NET projects)
  • Jenkins – SonarScanner for Jenkins
  • Azure DevOps – SonarQube Extension for Azure DevOps
  • Ant – SonarScanner for Ant
  • Anything else (CLI) – SonarScanner (Command Line)
Important: Embedded, C, C++, and custom projects usually use the SonarScanner (CLI).

Environment Setup

After downloading and extracting the scanner, add the following directory to the system PATH variable: 

<sonarscanner_path>/bin

This allows running the scanner from any terminal using: 

sonar-scanner
SonarScanner collects code metrics and uploads them to SonarQube, where results are displayed on the dashboard.

Bugs / Reliability

Bugs are coding mistakes that can lead to runtime errors or unexpected behavior.

  • Null pointer dereference
  • Division by zero
  • Incorrect loop conditions
Impact: Application crash or incorrect output.
Action: Must be fixed based on severity.

Vulnerabilities / Security

Vulnerabilities are confirmed security flaws that attackers can exploit.

  • Hardcoded credentials
  • Insecure cryptographic algorithms
  • Injection vulnerabilities
Impact: Data breach or system compromise.
Action: Fix immediately.

Security Hotspots

Security hotspots indicate security-sensitive code that requires manual review. They are not necessarily vulnerabilities by default.

  • Password handling
  • Encryption usage
  • File access permissions
Action: Review and mark as Safe or Fix Required.

Code Smells / Maintainability

Code smells are issues that affect readability and long-term maintainability.

  • Long methods
  • Complex conditional logic
  • Unused variables
  • Poor naming conventions
Impact: Increased technical debt.
Action: Refactor gradually.

Duplication

Duplication represents the percentage of repeated code across the project.

  • Harder maintenance
  • Higher risk of inconsistent fixes
Action: Refactor into reusable functions or modules.

Accepted Issues

Accepted issues are valid issues that are intentionally not fixed and marked as accepted.

  • Legacy code constraints
  • Low-risk issues
  • Time or cost limitations
Accepted issues represent known technical debt and should be reviewed periodically.

Code Coverage

Coverage shows how much of the code is executed by automated tests.

  • Line coverage
  • Branch coverage
Higher coverage reduces regression risk. Focus on critical and new code.

Quality Gate

A Quality Gate defines whether a project is ready for release.

  • No new critical bugs
  • No new vulnerabilities
  • Minimum coverage threshold
  • Controlled duplication
Result: Project Passes or Fails the Quality Gate.

Best Practices for Freshers

  • Fix issues while coding
  • Do not blindly accept issues
  • Always review security hotspots
  • Improve coverage for new code
  • Use SonarQube as a learning tool
