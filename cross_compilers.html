🛠 Cross Compilation in C – From Zero to Expert

This guide is meant for freshers in Embedded Systems to learn Cross Compilation — a key skill required to build firmware or applications for different hardware architectures like ARM, MIPS, etc.

🔰 What is Cross Compilation?

Cross compilation means compiling code on one machine (called host) to run it on another machine (called target), which often has a different CPU architecture or operating system.

Example: You compile a C program on your laptop for an STM32 microcontroller. Your laptop is x86 (Intel), STM32 is ARM Cortex-M → so you cross compile using a special compiler.

🧠 Basic Concepts

Term Description
Host System where code is written and compiled (your PC)
Target System where binary is executed (microcontroller or board)
Toolchain Set of tools (compiler, linker, assembler) for the target
Architecture CPU type like x86, ARM, MIPS, RISC-V etc.

🔧 Common Toolchains

Target Toolchain Prefix Example Compiler
ARM Cortex-M (bare metal) arm-none-eabi- arm-none-eabi-gcc
ARM Linux (e.g., Raspberry Pi) arm-linux-gnueabihf- arm-linux-gnueabihf-gcc
MIPS Linux mipsel-linux-gnu- mipsel-linux-gnu-gcc
Windows (from Linux) x86_64-w64-mingw32- x86_64-w64-mingw32-gcc

📄 Sample C Code

// hello.c
#include <stdio.h>

int main() {
  printf("Hello from embedded system!\n");
  return 0;
}

🧪 Native Compilation (x86)

$ gcc hello.c -o hello
$ ./hello
Hello from embedded system!

🚀 Cross Compilation (ARM Cortex-M)

Step 1: Install Toolchain

$ sudo apt install gcc-arm-none-eabi

Step 2: Compile for ARM

$ arm-none-eabi-gcc -mcpu=cortex-m3 -mthumb -o hello.elf hello.c

Step 3: Flash to Board

Use tools like ST-Link Utility, OpenOCD, J-Link, or pyOCD to load the hello.elf to your board.

🧰 Flashing Tools

  • ST-Link (STM32)
  • J-Link (Segger)
  • OpenOCD (Generic ARM)
  • esptool (ESP32/ESP8266)

📦 Makefile Example

CC = arm-none-eabi-gcc
CFLAGS = -mcpu=cortex-m4 -mthumb -Wall

all: main.elf

main.elf: main.c
	$(CC) $(CFLAGS) -o $@ $<

💡 Advanced: Using CMake Toolchain File

Create a file named arm-gcc-toolchain.cmake:

set(CMAKE_SYSTEM_NAME Generic)
set(CMAKE_SYSTEM_PROCESSOR arm)
set(CMAKE_C_COMPILER arm-none-eabi-gcc)
set(CMAKE_CXX_COMPILER arm-none-eabi-g++)

Then run:

$ cmake -DCMAKE_TOOLCHAIN_FILE=arm-gcc-toolchain.cmake .
$ make

📋 Good Practices

  • Use versioned toolchains to avoid inconsistency
  • Write Makefiles or use CMake to automate builds
  • Always test your code on real hardware
  • Use objdump, nm, size to inspect binaries

📚 Tools to Master

  • gdb – Debugging
  • objcopy – Convert .elf to .bin/.hex
  • map files – Inspect memory layout
  • Linker scripts – Custom memory management
  • Buildroot/Yocto – For embedded Linux targets

👨‍🔬 Final Notes

Cross compilation is essential for embedded systems engineers. Once you master it, you'll be able to write code on your PC and run it on any hardware, no matter how constrained. This skill bridges the gap between development and hardware deployment.
