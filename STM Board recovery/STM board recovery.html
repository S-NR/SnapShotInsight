STM32H735 Hot Plug / Under Reset Recovery

Snapshot guide for recovering an STM32H7 after PLL / high-frequency crash using BOOT0 method.

Problem Pattern Root Cause Recovery Steps Why It Works Prevention

Typical Failure Pattern

  • Increased system clock (e.g., 400–480 MHz).
  • Board powers normally.
  • ST-LINK detected.
  • Target voltage shown (~3.3V).
  • ❌ Cannot read Core ID.
  • ❌ "No STM32 target found".

This usually happens on STM32H735 (Cortex-M7) after wrong PLL configuration.

Root Cause

When increasing frequency incorrectly, the MCU crashes immediately after reset.

  • Wrong HSE value (DK uses 25 MHz).
  • Flash latency too low.
  • Voltage scaling not configured.
  • Switching to PLL before ready.
  • PLL multipliers outside limits.

The firmware enters HardFault before debugger attaches — making the MCU appear “dead”.

Guaranteed Recovery Method (BOOT0)

  1. Power OFF board (unplug USB).
  2. Set BOOT0 = HIGH (place jumper).
  3. Power ON board.
  4. Open STM32CubeProgrammer.
  5. Mode → Under Reset
  6. Reset Mode → Hardware Reset
  7. Frequency → 5 kHz
  8. Click Connect.
  9. Perform Full Chip Erase.
  10. Power OFF → Set BOOT0 LOW → Restart.

Why BOOT0 Recovery Works

When BOOT0 is HIGH, the MCU boots from internal ROM bootloader instead of user Flash.

  • Faulty firmware is completely bypassed.
  • No PLL misconfiguration executes.
  • Debugger can safely connect.

This method always works unless Option Bytes are locked.

How to Prevent This Next Time

  • Set correct HSE value (25 MHz for DK).
  • Configure voltage scaling first.
  • Set correct Flash latency before switching clock.
  • Increase frequency gradually.
  • Test intermediate frequencies.

Golden Rule

If:
  ST-LINK detected
  Target voltage OK
  Cannot read Core ID
  After clock change

Then:
  It is almost always PLL / Flash latency crash.
  Use BOOT0 recovery.
