Embedded Firmware Development Insights – Knowledge Base

?? Issue Overview

When using VS Code alongside embedded IDEs (MPLAB X, STM32CubeIDE, Keil, etc.), source files may be silently modified. This typically happens due to automatic encoding detection and file formatting behavior.

? Why Does This Happen?

  • VS Code defaults to UTF-8 encoding
  • Embedded IDEs often use Windows-1252 (ANSI)
  • Auto-guess encoding rewrites special characters
  • Line ending normalization changes file structure

? What Problems Can It Cause?

  • Symbol corruption (°C, µA, m², etc.)
  • Unexpected Git diffs
  • Build inconsistencies
  • UI display glitches in embedded systems

?? How Do We Prevent It?

The solution is to lock encoding at the workspace level and standardize behavior across the entire project.

? Best Practice Recommendation

  • Define encoding at project level (.vscode/settings.json)
  • Convert legacy files once
  • Reload VS Code after changes
  • Use .gitattributes for team safety
  • Avoid mixing UTF-8 and ANSI in embedded firmware
