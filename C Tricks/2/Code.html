Snapshot Insight · Think before you compile

The Question

What does the following C program do when executed?

#include <stdio.h>

int main(void)
{
    int i = 0;
    printf("%d %d %d\n", i++, i++, i++);
    return 0;
}

Your Answer:

Explanation

The problem lies in this statement:

printf("%d %d %d\n", i++, i++, i++);
  • i++ modifies i
  • The order of evaluation of function arguments is not defined
  • i is modified multiple times without a sequence point

Result: This program has undefined behavior.

On many systems, it may appear to print: 

2 1 0

But this output is not guaranteed. Different compilers, architectures, or optimization levels may produce different results.

⚠️ Takeaway: Never modify the same variable multiple times in a single expression.

What if the compiler optimization level is -O2?

With optimization enabled, the compiler may:

  • Reorder argument evaluation
  • Assume impossible states never occur
  • Generate completely different output

This means the program may:

  • Print different values
  • Print nothing meaningful
  • Behave differently across builds

⚠️ This is especially dangerous in embedded and safety-critical systems.

Rule of thumb:
Never write code that depends on argument evaluation order.
