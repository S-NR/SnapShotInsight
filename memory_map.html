🧠 Embedded System Memory Map

📊 Visual Representation

+---------------------------+ ← Top of memory
|    Peripheral Registers   | ← Memory-mapped I/O (e.g., UART, SPI)
+---------------------------+
|         SRAM (RAM)        |
|  - Global Variables       |
|  - Stack (grows downward) |
|  - Heap (grows upward)    |
+---------------------------+
|       Reserved Gap        |
+---------------------------+
|        Flash Memory       |
|  - Program Code (.text)   |
|  - Const Data (.rodata)   |
+---------------------------+
|       Vector Table        | ← Reset & interrupt vectors
+---------------------------+ ← 0x00000000

📌 Explanation of Sections

SectionMemory TypeDescription
Vector TableFlashStartup vectors (Reset, NMI, IRQ handlers)
.textFlashAll functions and executable code
.rodataFlashRead-only constants and strings
.dataRAMInitialized global/static variables
.bssRAMUninitialized global/static variables
StackRAMFunction call information, grows downward
HeapRAMDynamic memory (malloc, etc.) grows upward
Peripheral RegistersMapped MemoryUsed to control hardware (GPIO, UART, etc.)

📍 Example Address Mapping (STM32F103)

AddressDescription
0x00000000Start of Flash / Vector Table
0x08000000Base of Flash Memory (code)
0x20000000Start of SRAM (RAM)
0x40000000Peripheral Registers (I/O)
0xE000E000System Control Space (NVIC, SysTick)

🛠 Tips for Freshers

  • Understand which memory your variables go to — Flash or RAM
  • Check .map file or debugger memory viewer
  • Stack overflows can crash your program — watch recursion and large arrays
  • Use const to store in Flash and save RAM
  • Always know the total size of your Flash and RAM before compiling
