Advanced C Interview Questions (7–9 Yrs Experience)

1. Explain memory layout of a C program.

A typical C program is divided into several segments:

  • Text (Code) Segment: Stores compiled machine instructions. Usually read-only.
  • Data Segment: Stores initialized global and static variables.
  • BSS Segment: Stores uninitialized or zero-initialized global and static variables.
  • Heap: Used for dynamic memory allocation (malloc, calloc, etc.).
  • Stack: Function call frames, local variables, return addresses.
| Text | Data | BSS | Heap (grows up) ... | Free Space | ... (grows down) Stack |

3. How would you debug memory leaks?

- Use valgrind, mtrace, or address sanitizers.
- Wrap malloc and free to log allocations.
- Maintain allocation counters.
- Use static analysis (Coverity, SonarQube).
- In embedded: Use a custom heap monitor with watermarking.

4. Explain volatile and const together.

const volatile int *reg;
- const: Application cannot modify the value.
- volatile: Value can change unexpectedly (e.g., hardware register).
Example: A read-only hardware status register updated by hardware.

5. Prevent structure padding/alignment issues across compilers?

- Use #pragma pack(1) (MSVC) or __attribute__((packed)) (GCC).
- Explicitly serialize to byte streams instead of raw struct copy.
- Example: 

struct __attribute__((packed)) {
  uint8_t a;
  uint16_t b;
  uint32_t c;
};

6. Function pointers? Use-case?

Function pointers allow storing addresses of functions.
Use cases: Callbacks, interrupt vectors, jump tables. 

void hello(int x) { printf("%d\n", x); }
void (*fp)(int) = hello;
fp(42);

7. Deep copy vs Shallow copy?

  • Shallow copy: Copies only pointers, not the underlying data.
  • Deep copy: Allocates new memory and copies data recursively.

8. Reentrant vs Non-Reentrant?

- Reentrant: Safe to call simultaneously in multi-threaded/ISR context, no static/global states.
- Non-Reentrant: Uses static/global data, not thread/ISR safe.
Example: strtok() is non-reentrant, strtok_r() is reentrant.

9. What happens if malloc fails?

It returns NULL. Always check before dereferencing.
Example: 

int *p = malloc(100 * sizeof(int));
if (!p) {
   // Handle error
}

10. Race conditions? Prevention?

Race condition: Multiple threads/ISRs access shared data concurrently without proper synchronization.
Prevention:

  • Mutexes and semaphores.
  • Atomic operations.
  • Disable interrupts in critical sections (embedded).
  • Use memory barriers with volatile or atomic built-ins.
