1) Memory & Pointers

Q: Difference between const int *p, int * const p, and const int * const p?
  • const int *p: pointer to const int — pointer can change; value cannot.
  • int * const p: const pointer to int — pointer cannot change; value can.
  • const int * const p: const pointer to const int — neither can change.
Q: What happens if you dereference an unaligned pointer on ARM Cortex‑M?
Some cores permit unaligned 16/32‑bit access but with penalties; others may HardFault. Align to natural word boundaries for correctness & speed.
Q: Difference between stack, heap, static, and global memory?
  • Stack: automatic lifetime, fast, limited.
  • Heap: dynamic (malloc), fragmentation risk.
  • Static: persists for program lifetime, internal linkage if inside function.
  • Global: program‑wide visibility, program lifetime.
Q: How would you implement a simple malloc() for embedded?
#define HEAP_SIZE 1024
static unsigned char pool[HEAP_SIZE];
static size_t off = 0;
void* my_malloc(size_t sz){
  if (off + sz > HEAP_SIZE) return NULL;
  void* p = &pool[off];
  off += sz; // bump allocator
  return p;
}
Use fixed pools or free lists for production; avoid fragmentation.
Q: Function pointers example?
void hello(void){ puts("Hi"); }
void (*fp)(void) = hello;
fp(); // calls hello
Useful for callbacks, ISRs, driver vtables.

2) Bitwise Operations

Q: Count number of set bits efficiently.
int popcount(unsigned int n){
  int c = 0; while(n){ n &= (n-1); ++c; } return c;
}
Q: Extract the leftmost (MSB) set bit.
unsigned int msb_only(unsigned int n){
  if(!n) return 0;
  n |= n>>1; n |= n>>2; n |= n>>4; n |= n>>8; n |= n>>16;
  return n ^ (n>>1);
}
Q: Check if number is power of 4.
int is_pow4(int n){ return (n>0) && !(n & (n-1)) && (n & 0x55555555); }
Q: Reverse bits in a byte.
unsigned char rev8(unsigned char b){
  b = (b & 0xF0)>>4 | (b & 0x0F)<<4;
  b = (b & 0xCC)>>2 | (b & 0x33)<<2;
  b = (b & 0xAA)>>1 | (b & 0x55)<<1;
  return b;
}

3) Structures & Unions

Q: Padding vs packing?
Padding aligns members for performance; packing removes padding (smaller size, potential slowdown). 
struct A { char c; int i; }; // likely size 8 due to padding
#pragma pack(1)
struct B { char c; int i; }; // size 5, no padding
#pragma pack()
Q: Why sizeof(struct) differs across compilers?
Different ABI alignment rules, packing pragmas, and target architecture constraints.
Q: Map hardware registers with struct.
typedef struct { volatile uint32_t CR, SR, DR; } ADC_TypeDef;
#define ADC1 ((ADC_TypeDef*)0x40012400u)
Q: Use union to alias float and int.
union { float f; uint32_t u; } U;
U.f = 3.14f; printf("%08x\n", U.u);

4) Volatile & Optimization

Q: Why use volatile?
Variables may change outside normal flow (ISRs, MMIO). Prevents unwanted optimization of reads/writes.
Q: Difference between volatile int i and int volatile *p?
volatile int i marks the variable as volatile; int volatile *p is a pointer to a volatile int (target is volatile).
Q: Are volatile accesses atomic or reorderable?
They are not atomic and compilers must not reorder volatile accesses relative to each other, but you still need locks/critical sections for atomicity.
Q: Why not rely on volatile for atomicity?
It only prevents optimization; it does not prevent race conditions. Use critical sections or hardware atomics.

5) Concurrency & RTOS

Q: Protect shared variables between ISR and Task?
Use short critical sections (__disable_irq/__enable_irq) or RTOS primitives (mutex/semaphore) depending on context.
Q: Explain priority inversion and solution.
High-priority task blocked by low-priority task holding a resource while a medium task runs. Use priority inheritance or ceilings.
Q: Circular buffer (UART Rx) sketch.
#define N 128
volatile uint8_t q[N]; volatile uint16_t h=0,t=0;
void put(uint8_t d){ q[h++ & (N-1)] = d; }
uint8_t get(void){ return q[t++ & (N-1)]; }
Q: What if ISR is too long?
Missed interrupts, increased latency, watchdog resets. Keep ISRs short; defer work to tasks/DMAs.

6) Tricky / Edge Cases

Q: Output of printf("%d %d %d\n", x, x++, ++x);
Undefined behavior (multiple modifications of x between sequence points). Avoid such expressions.
Q: #define MAX 100 vs const int MAX = 100;
Macro is a textual substitution (no type, no scope); const is typed, scoped, debuggable, respects the compiler.
Q: Why is memcpy unsafe for overlapping regions? Alternative?
memcpy may clobber source on overlap. Use memmove which handles overlap safely.
Q: What if main() has no return in C99?
In hosted C99, reaching end of main implies return 0;. In freestanding/embedded, behavior may vary—be explicit.

typedef struct {
  uint8_t version; // 4 or 6

Q: Debounce a switch (simple).
bool debounce_read(GPIO_TypeDef* p, uint8_t pin){
  int stable = 0; for(int i=0;i<5;i++){ stable += gpio_read(p,pin); delay_ms(10); }
  return stable >= 3;
}
Q: UART protocol finite‑state machine.
typedef enum { IDLE, START, DATA, STOP } uart_st;
void uart_fsm_step(int bit){
  static uart_st s = IDLE; static uint8_t b=0,cnt=0;
  switch(s){
    case IDLE: if(bit==0){ s=START; cnt=0; b=0; } break;
    case START: s=DATA; break;
    case DATA:  b |= (bit & 1) << cnt++; if(cnt==8) s=STOP; break;
    case STOP:  // use byte b
               s=IDLE; break;
  }
}
