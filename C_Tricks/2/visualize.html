🧠 Understanding i++, i++

Visual explanation · No assumptions · No shortcuts

Case 1: Independent post-increments (safe)

i++;
i++;
i = 0 Initial value
➜
i = 1 After first i++
➜
i = 2 After second i++

Each increment is a separate statement. Each statement completes before the next begins.

✔ Safe and well-defined

Case 2: Single post-increment in an expression (safe)

x = i++;
i = 0 Before evaluation
➜
x = 0 Old value returned
➜
i = 1 Increment applied

Post-increment performs two actions:

  • Return the old value
  • Increment the variable

✔ Still well-defined

Case 3: The trap — i++, i++

printf("%d %d\n", i++, i++);

What goes wrong?

The order of evaluation of function arguments in C is not defined.

i = 0 Initial value
➜
i++ Which one executes first?
➜
i++ No guaranteed order

⚠ The compiler is free to evaluate arguments in any order

One possible execution (not guaranteed)

i = 0 Initial
➜
i++ → 0 i becomes 1
➜
i++ → 1 i becomes 2

This may print: 

1 0

Another compiler might print: 

0 1

❌ Output is not reliable

Why this is dangerous (C language rule)

In this expression: 

printf("%d %d\n", i++, i++);

i is modified more than once without a sequence point.

  • Multiple side effects
  • No guaranteed evaluation order

This results in undefined behavior.

At higher optimization levels (-O2):

  • Output may change
  • Behavior may differ across compilers
  • Code may break unexpectedly

Correct mental rule

i++; i++;✔ Safe
x = i++;✔ Safe
i++, i++❌ Never
printf(i++, i++)❌ Never

Rule of thumb: Never modify the same variable more than once in a single expression.
