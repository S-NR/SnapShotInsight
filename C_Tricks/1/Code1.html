The Question

What does the following C program do when executed?

#include <stdio.h>

int main() {
    int value = 0;
    for (value = 0; value < 4; value = value++)
    {
        printf("%d --\n", value);
    }
    return 0;
}

Your Answer:

Explanation

visualize the concept

The problem lies in this statement:

value = value++;
  • value++ returns the old value of value
  • The increment happens internally
  • The assignment overwrites the increment

Net effect: value never changes.

The loop effectively becomes:

value = 0;
while (value < 4) {
    printf("0 --\n");
}

🔁 This results in an infinite loop printing 0 --.

⚠️ Takeaway: Never combine assignment and post-increment on the same variable.

What if the compiler optimization level is -O2?

This is where things get even more interesting.

The expression value = value++; causes the variable value to be modified and read without a sequence point.

According to the C standard, this results in undefined behavior.

  • The compiler is free to assume value does not change
  • Or remove the loop entirely
  • Or produce behavior that differs between builds

With optimization level -O2 enabled, the compiler may:

  • Optimize away the increment
  • Reorder operations aggressively
  • Generate output that differs from -O0

This means the program:

  • May loop infinitely
  • May terminate unexpectedly
  • May behave differently across compilers or targets

⚠️ This is why relying on such expressions is dangerous — especially in embedded and safety-critical systems.

Rule of thumb: Never write code whose correctness depends on evaluation order.
