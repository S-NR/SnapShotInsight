Existing design and code

T1 · SD parameter-file import

· flow: importLAR_File() → read_line() → systemInfoDetails() → parse_token() → row handlers → MRAM.

#LocationExisting codeDefect
1aread_line() :364–410Copies byte by byte until \n / EOFNo length limit buffer size not passed in
1bimportLAR_File() :2079–2092char str[500] on the stackLine ≥ 500 bytes overwrites the stack
1csystemInfoDetails() :1076–1103sprintf(str1, "%s", token) into str1[50]Field ≥ 50 bytes overwrites the stack
1d:538, :542, :610strcpy into name[8]Name ≥ 8 bytes overwrites adjacent static data

The device's own export writes rows of at most 493 bytes (typically ~130), so a 500-byte limit accepts every file the device can produce. The uncommitted VIEGA change (adc_offset in rows 8/9) must be merged first.

T2 · JTAG

: DDPCON = 0x0008 turns trace off but leaves JTAG on (bit 3 = JTAGEN). Port A only uses RA9/RA10, so turning JTAG off has no GPIO side effect.

T3 · Config bits

: CP = OFF, BWP = OFF, PWP default off. Only one MPLAB X configuration ("default") exists.

T4 · Service interface

CMD_ENABLE (raw MRAM write %MW) is undefined only for Modbus/M-Bus builds; nothing at build time stops it or debug output in other variants.

Changes

C1 · T1

Bounded import parsing

IMPORT_LINE_MAX 500; read_line(fin, buf, size) stores at most size − 1 bytes, returns code 2 for over-long lines; the row is skipped (never truncated) and the existing import-error message is shown. snprintf in systemInfoDetails(); bounded name copies. Review other FSfread sites.

C2 · T2

JTAG off in release

#ifdef RELEASE_BUILD → DDPCON = 0x0000, else keep 0x0008 for development. Correct the misleading comment.

C3 · T3

Production config bits

CP = ON, BWP = ON, PWP over the bootloader pages in release builds, set also in the production programming image and verified with MPLAB IPE. Depends on Q-01 and Q-06.

C4 · T4

Release build guard

New MPLAB X configuration production with -DRELEASE_BUILD; #error if CMD_ENABLE or debug flags are set. Released hex files are built only from production.

Expected flash impact: about 100–300 bytes; confirmed by the MEM_OPT_*_1 gate (< 98 % of 0x73000) for every language build.
