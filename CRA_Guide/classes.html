Product classes & conformity routes

Products are classified by their core functionality (Art. 7, 8; Annex III, IV). A product that merely contains an OS or a microcontroller is not automatically "important". The class decides whether self-assessment is allowed.

The Commission published technical descriptions of these categories in Implementing Regulation (EU) 2025/2392. Some websites still show the 2022 proposal's lists (where operating systems were Class II). Use the final 2024 text only.

Conformity modules (Annex VIII)

Module A

Internal control

The manufacturer assesses conformity itself, writes the technical file and signs the DoC. Still a legal declaration that market surveillance can audit.

Module B + C

EU-type examination + conformity to type

A notified body examines the design (B); the manufacturer ensures production matches the examined type (C).

Module H

Full quality assurance

A notified body approves and monitors the manufacturer's whole quality system for design, production and vulnerability handling.

Rule of thumb for engineers

If the product has firmware and any interface (bus, USB, radio, Ethernet, SD card, debug port used in the field), assume CRA applies, default class, Module A. Then check whether the core function puts it in Annex III/IV. Gateways and network interface modules are the usual surprise: they can be Important Class I.
