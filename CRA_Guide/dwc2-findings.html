DWC2: findings F1–F12

Static review of source, build configuration, linker script and the shipped bootloader hex, against CRA Annex I Part I. Nothing was run on hardware and no source files were modified. Severity is engineering judgement with the physical/OT context considered.

Findings

F1Firmware update is not authenticatedHighI.2(c), (f)
Evidence
The bootloader reads SYSCTRL.hex from the SD card at reset and programs flash. Its only checks are the HEX record checksum and the address range (strings in ). App reset vector 0x9D00D000 in . USB MSD lets a PC write that file.
Risk
Arbitrary or modified firmware: falsified measurement and totalizer values, a permanently compromised device, or a bricked unit. → R01
Fix
Sign release images (ECDSA P-256 or Ed25519); verify in the bootloader before erase/program; version counter for anti-rollback; never erase the running app before the new image is verified. Software verification (micro-ecc, Monocypher) fits in the 52 KB bootloader. → S1 Nitrokey secure boot
Dependency
Bootloader source is not in this repo (question Q-01).
F2Flash code protection and write protection disabledHighI.2(j), (k), (f)
Evidence
sets #pragma config CP = OFF, BWP = OFF. Bootloader hex DEVCFG0 = 0x7FFFFFFF → CP, BWP, PWP all off. Background debugger off (DEBUG = 11), but ICSP read-out is possible. JTAG pins RA0/1/4/5 and trace RA6/7 are never disabled (JTAGEN defaults on).
Risk
Firmware, algorithms and embedded secrets can be extracted with a standard programmer; boot flash can be overwritten. → R02, R03
Fix
Production config: CP = ON, PWP covering the bootloader, BWP = ON, JTAG disabled at startup. Separate debug and production configurations; verify in the production programming procedure. → Quick win Q1
F3Hard-coded master password 5555HighI.2(b), (d)
Evidence
#define DEFAULT_PASSWORD 5555. Accepted to deactivate any user password in . falls back to it when protect.dwc is unreadable.
Risk
Same unlock code on every device → full configuration access, calibration, factory reset. Exactly what "secure by default" targets. → R04
Fix
Device-unique recovery: challenge-response derived from the serial number with a Systec-held key. → S2 user levels
F4Weak PIN scheme, reversible storage on removable mediaMedium/HighI.2(d), (e)
Evidence
4-digit numeric PIN. password_encode() in computes key = SUBn − digit × LETTERn, trivially reversible, stored in protect.dwc on SD. No attempt counter or lockout. PIN is optional: password == 0 disables all gates in .
Risk
PIN readable from SD or over USB. → R05
Fix
Salted SHA-256 in MRAM, no copy on SD; attempt limiting with back-off; consider PIN required at commissioning or document the default in Annex II.
F5Stack buffer overflow in parameter-file importHighI.2(a), (k)
Evidence
read_line() in copies bytes until \n with no length limit. importLAR_File() (around line 2079) passes char str[500] on the stack.
Risk
Any line > 499 characters in a parameter file on the SD card (writable over USB) overwrites the stack: crash or code execution. A "known exploitable vulnerability" at release. → R06
Fix
Pass the buffer size, stop at size − 1, discard the rest of an over-long line. Fuzz the import parser on a host build (AFL++/libFuzzer). Review other FSfread/strcpy sites.
Sketch
static int read_line(FSFILE *f, char *buf, size_t size)
{
    size_t n = 0; char c;
    while (FSfread(&c, 1, 1, f) == 1) {
        if (c == '\n') break;
        if (n + 1 < size) buf[n++] = c;   /* drop excess bytes */
    }
    buf[n] = '\0';
    return (int)n;
}
F6Parameter/calibration integrity not protectedMediumI.2(f)
Evidence
Calibration, MUS parameters, flow-error tables and com settings written to MRAM via mram_wr_byte() (e.g. ). No CRC/MAC over stored blocks. SD import writes calibration values after range checks only.
Risk
Undetected corruption or manipulation of calibration. → R07
Fix
CRC (minimum) or MAC per parameter block, verified at boot, corruption reported. Calibration import only at service level; log it.
F7Unauthenticated persistent changes via M-BusLow/MediumI.2(d), (j)
Evidence
persists primary/secondary address changes. Open TODO: "check values with struct tValue::iWritable set".
Context
M-Bus has no authentication by design (EN 13757); address changes are a normal feature. → R09
Fix
Resolve the TODO; document the OT trust assumption; optional lock for address changes.
F8Modbus TCP converter (to verify)MediumI.2(d), (h), (j)
Evidence
MODBUSTCP_ENABLE active (). Default IP 192.168.100.10/24, port 502 (SYSCTRL.h:2960–2972). Converter configured over UART1 with frames delimited by fixed constants 0x12345678/0x87654321 ().
Open questions
Network-side config (web UI, default credentials)? Own firmware updates? TCP flood robustness? (Q-04)
Positive
DWC2 Modbus map is read-only, so network exposure is limited to reading and DoS. → R08
Fix
Include the converter in risk assessment and SBOM; vendor security info; segmentation guidance in Annex II.
F9No security event logMediumI.2(l)
Evidence
No logging of PIN changes, failed PIN entries, config/calibration import, factory reset or firmware update. SD logger records measurement data only.
Fix
Small ring-buffer security log in MRAM (event, RTC timestamp, source interface), exportable via SD and the diagnostics screen.
F10Watchdog disabledLow/MediumI.2(h)
Evidence
#pragma config FWDTEN = OFF (); ENABLE_WATCHDOG commented out (SYSCTRL.h:826).
Fix
Enable after a timing review of long blocking paths (SD access, modbusTCPInit()/modbusTCPRead() UART loops, USB MSD transfers). → R10
F11Dormant service backdoor code (compiled out)LowI.2(j)
Evidence
: unauthenticated RS232 commands for SD delete/copy/mkdir and arbitrary MRAM write (%MW, cmd_mram() :769–787); unbounded strcpy (:437, :745). Guarded by CMD_ENABLE, not defined in the current SYSCTRL.h.
Fix
Build-time #error if CMD_ENABLE is set in a release configuration, or remove the code. → R13
F12Weak randomness for activation keyLowI.2(d)
Evidence
Generate_Random_Password() seeds srand(rtc.seconds * rtc.minutes) (): at most 3,600 seeds, many 0. Key stored on SD in the F4 format.
Fix
Device-unique, server-side-generated activation code. Business rather than safety risk. → R14

Limits of this analysis

  • Static review only: no hardware tests, no fuzzing, no binary diff of shipped images.
  • Bootloader behaviour inferred from strings and config words in the hex, not from source.
  • Third-party versions not yet checked against CVE databases (first P0 item).
  • Variant #ifdef combinations (1CH/2CH, languages, VIEGA) checked only for the flags named above.
  • MRAM handling and USB MSD SCSI handling not reviewed in depth.
