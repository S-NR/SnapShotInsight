Engineering Insight: Preventing VS Code File Corruption in Embedded Projects

Problem Overview

When using VS Code alongside embedded IDEs like MPLAB X or STM32CubeIDE, source files may be silently converted from Windows-1252 (ANSI) to UTF-8. This causes symbol corruption and unwanted Git diffs.

Workspace-Level Encoding Lock

Create a .vscode/settings.json inside project root:

{
  "files.encoding": "windows1252",
  "files.autoGuessEncoding": false,
  "files.eol": "\r\n"
}

This ensures encoding is enforced only for this project.

Fix Existing Files (One-Time Step)

  1. Open file
  2. Click encoding (bottom-right)
  3. Reopen with Encoding ? Windows-1252
  4. Save with Encoding ? Windows-1252

When Settings Do Not Refresh

If encoding does not apply immediately:

  • Save all files
  • Close VS Code completely
  • Reopen project
  • Or use Ctrl + Shift + P ? Reload Window

Optional Git Protection

Create a .gitattributes file:

*.c text working-tree-encoding=windows-1252
*.h text working-tree-encoding=windows-1252
*.txt text working-tree-encoding=windows-1252

Safe Symbol Usage

"m^2"
"m^3"
"degC"
"uA"

These are safer for embedded firmware unless full Unicode support is verified.
